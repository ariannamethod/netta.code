# Seventh engineering pass — credit follows the stored action

Baseline: `7ade976a7d5b526c0cb6ce482fdbd047584bf694`. This pass connects the existing temporal game targets to the executed derivation of the final selected action. Both standalone bodies retain exact-source execution, their own memory architecture and the standard-library dependency boundary.

## Installed capability

`2048.py play --decision-credit provenance` selects the saved contract `2048-action-provenance-v1`. The target remains the previous eight-move discounted return, with discount 0.9 and episode-centered normalization. The new mechanism changes which generated choices receive that target.

An optional CPython 3.12 observer records dependencies between actual instruction occurrences. A load points to the current stored value; arithmetic combines its executed inputs; guarding conditions participate in the assignments they control. Loop occurrences have separate event identities. The final executed store to `action` roots the selected dependency graph. This bookkeeping observes ordinary CPython execution; generated bytes and indentation are unchanged.

Instruction positions need careful projection. Some compiler-generated operations cover a whole expression that contains an unexecuted alternative. Semantic source atoms therefore replace broad bytecode envelopes for credit. The regression cases include short-circuiting, conditional expressions, synthetic dictionary-key tuples, folded constants, comprehension-local restoration, Unicode and multiline operators.

The observer returns half-open UTF-8 byte spans bound to source, observation and resulting action. The shared learning core validates the exact generated bytes, recorded token/offset/key alignment, and containment of credit within that invocation's trace and the episode trace before changing memory. Only overlapping sampled choices qualify; a deterministic source gap does not invent credit for a preceding choice. Repeated occurrences of the same generation association receive one mean target per episode. A learned byte unit may overlap both selected and unselected text; positive overlap makes that whole association eligible. After decision experience has been acquired, changing its contract or attribution requires a separate saved life.

The explicit receipt scope is **last stored action, aggregate container origins, later negative guards excluded**. Read-only containers carry their combined origins. A later false condition after the final action assignment is outside this graph. Nested functions, generators, mutation and other unsupported constructs retain their actual gameplay and ordinary episode learning, with empty additional provenance credit. Other CPython versions report unsupported provenance. Default observation remains off, preserving existing behavior and snapshot serialization.

## Fixed 2048 comparison

Two replicas per arm, 128 learning attempts and 64 fresh evaluation attempts in each. All arms observe provenance equally. The temporal arm retains executed-line eligibility. The coverage control uses exact executed source spans on supported decisions. The provenance candidate uses the selected action spans on those same supported decisions. This controls for the observer's support boundary as well as the difference between line and byte attribution.

The advancement rule was registered before the run: exceed coverage in both replicas, gain at least 25 pooled completed-score points per raw attempt, retain at least coverage's mean played score, and equal or exceed the temporal arm's completed score per raw attempt. ## Runtime cost

The corrected observer caches static source-atom projection by instruction offset. On the same 128 recorded observations of one 874-byte real policy, cached and uncached complete receipts, detailed selected graphs and trace hashes are identical. CPU time falls from **12.048959 to 7.227206 seconds**, a 40.0% reduction for this fixed-input check.

In a separate unchanged-worker replay with the ten-second CPU cap, the same policy completes **128 moves and 1,272 points** both with tracing off and on. All actions, observations and board transitions match. Child CPU is **1.589576 seconds off** and **7.234012 seconds on**, with peak RSS of 25,168 and 29,248 KiB. Both workers remain alive until normal cleanup. The earlier observer diagnostic had stopped after 110 moves; its source and receipts remain archived with that superseded implementation. ## Implementation references and storage

The observer uses documented [CPython 3.12 instruction and position information](https://docs.python.org/3.12/library/dis.html) and [opcode trace events](https://docs.python.org/3.12/library/sys.html#sys.settrace). Comprehension scope handling follows the inlining and local restoration described in [PEP 709](https://peps.python.org/pep-0709/).

Public reports contain compact protocols, comparisons and audit receipts. Complete attempts, frozen source, checkpoints and reproduction tools are retained in the [separate compressed archive](private-archive-inventory.json).
